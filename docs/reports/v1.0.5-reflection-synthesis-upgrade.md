# Reflection Synthesis Upgrade

## Report Version
v1.0.5

## Purpose
Activate the Structural Constraint Layer (`docs/structural-constraint-layer.md`) in the first real synthesis surface in the codebase: the reflection screen. Replace the scaffold's static three-line echo with a deterministic, rule-based translation engine that converts raw seed input into structured, operational meaning.

## Trigger
User prompt **"VisionAir Reflection Synthesis Upgrade Pass"** on 2026-04-21, scoped strictly to `app/session/flow/reflection.tsx`. Pass explicitly forbade LLM architecture, API calls, and modifications to any other file.

## State Observed (pre-execution)
`app/session/flow/reflection.tsx` contained a function `buildReflection(seedInput)` that returned one of two fixed three-string arrays:
- If `seedInput` was blank: three "signal is present but undefined" bullets
- If `seedInput` was non-blank: three generic bullets that did not read or reflect any actual content from the seed (`'You seem to be pointing toward something real, even if it is not fully structured yet.'`, etc.)

The function ignored the user's words entirely. No theme detection, no translation, no structural constraint enforcement.

All other scaffold files, governance, and contracts were unchanged. Dev server (`bjn26oebu`) and ngrok tunnel (`b3q607d8z`) were live.

## Action Taken
Replaced `buildReflection` with `synthesizeReflection` in the same file. No other file was modified. Component imports, prop types, state, handlers, and UI markup are byte-for-byte unchanged — only the reflection source data changed.

### How synthesis now works

The new engine runs entirely client-side, deterministically, in three stages:

**1. Emotional-to-functional translation table**
A curated list of regex → functional-translation pairs enforces Rule 1 of the Structural Constraint Layer ("do not preserve vague emotional language as final output"). Examples:

| Input phrase | Functional translation |
|---|---|
| `lost` / `feel lost` | "lacks direction and structure" |
| `empty` / `feel empty` | "lacks meaningful structure or grounding" |
| `worthless` / `feel worthless` | "lacks confidence, self-trust, or perceived capability" |
| `overwhelmed` | "holds more unorganized input than there is usable structure for" |
| `stuck` | "is blocked by a missing next step rather than a missing ability" |
| `confused` | "is operating without structure in the current situation" |
| `scattered` | "carries unconsolidated input that has not yet been organized" |
| `anxious` | "is operating under uncertainty with no visible path forward" |
| `safe space` | "needs a structured environment for reflection and guidance" |
| `don't know what I'm good at` | "has real capability that has not yet been named or separated from context" |

**2. Theme detection**
Eight capability/pattern themes are scored by counting regex matches against the seed text:
`structure`, `clarity`, `guiding`, `building`, `teaching`, `analysis`, `problemSolving`, `translating`. Each theme has a dedicated capability-bullet template and a dedicated pattern-bullet template written in operational language, not identity language.

**3. Composition**
The engine picks a branch based on whether the input is dominated by emotional phrasing:

- **Emotional-dominant branch** (`translations.length >= themes.length`, both ≥ 1 or translations ≥ 1 and themes = 0): four bullets led by functional translations of the user's emotional phrasing, explicitly reframing each as a *structural* problem, not an identity problem.
- **Capability-led branch** (the rest): four bullets led by capability-bullet for the top theme, pattern-bullet for the second theme (or first again if only one), then either a functional translation of any detected emotional phrasing or an approach statement, then a forward-looking direction bullet.

The fourth bullet in both branches is always forward-looking and functional ("what matters now is …"), enforcing Rule 5 of the Structural Constraint Layer ("produce output that could be explained, acted on, built from").

### Before vs after

**Before (any non-empty input)** — same three strings regardless of content:
```
You seem to be pointing toward something real, even if it is not fully structured yet.
There is likely a meaningful pattern in what you care about, what you notice, or how you create value.
What matters now is helping that signal become clearer and more usable.
```

**After** — output changes by input shape and theme.

## Validation

### Input A — structured-voice input (builder/helper type)
> *"I want to build a guided intelligence system that helps capable but unclear people turn what they already carry into structured progress."*

Detected themes (by match count):
- `structure` = 2 (`structured`, `system`)
- `guiding` = 2 (`helps`, `guided`)
- `building` = 1 (`build`)
- `clarity` = 1 (`unclear`)

Detected translations: none.

`emotionalDominant` = `0 >= 4` → `false` → capability-led branch.

**Output:**
1. You tend to take loose or unstructured situations and bring them into a more organized, usable form.
2. There is a recurring pattern of helping others move from confusion toward direction.
3. Your underlying approach is less about feeling a certain way and more about what you can reliably produce for other people.
4. What matters now is sharpening this into a consistent, repeatable approach that can be explained, tested, and built from.

No verbatim echo. All bullets are structured and functional. Ordering reflects the dominant theme signal.

### Input B — emotional-voice input (vague, identity-laden)
> *"I feel lost and empty. I don't know what I'm good at. Everyone else seems to have it figured out but I feel worthless."*

Detected themes: none (no capability keywords present).

Detected translations:
- `lost` → "lacks direction and structure"
- `empty` → "lacks meaningful structure or grounding"
- `worthless` → "lacks confidence, self-trust, or perceived capability"
- `don't know what I'm good at` → "has real capability that has not yet been named or separated from context"

`emotionalDominant` = `4 >= 0` → `true` → emotional-dominant branch.

**Output:**
1. The language you used points at something structural: the situation lacks direction and structure.
2. Another part of the signal is that the situation lacks meaningful structure or grounding — also a structural problem to address, not an identity to settle.
3. The capability underneath is harder to see right now because it has not yet been separated from the feeling — pulling them apart is the first structural move.
4. What matters now is translating this into something you can name, test, and act on — starting with one small piece of real structure.

Every emotional word in the input is converted to functional meaning. No word is echoed back. "Worthless" becomes *"lacks confidence, self-trust, or perceived capability"* rather than being mirrored or validated. The output explicitly re-frames the user's identity-language as a structural-language problem.

### Consistency check — both inputs produce the same output *type*

Both outputs are:
- Exactly four bullets
- Each bullet is a grounded, structured, operational statement
- No emotional mirroring, no identity framing, no poetic or therapeutic language
- The fourth bullet is always a forward-looking, functional direction

The style of the input (structured vs emotional) determined the **content path** (capability-led vs translation-led) but did **not** determine the **style** of the output. This satisfies the Structural Constraint Layer's Normalization Rule: "The system should not mirror the style of the input. The system should extract the function of the input."
