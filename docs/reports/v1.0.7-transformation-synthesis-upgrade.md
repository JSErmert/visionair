# Transformation Synthesis Upgrade

## Report Version
v1.0.7

## Purpose
Activate the Structural Constraint Layer in the second synthesis surface — the Transformation Promise screen. Replace the scaffold's raw before+after string concatenation with a deterministic structural translator that converts emotional, identity, and vague phrasing into structured before/after state descriptions, both in the live transformation card and in the downstream blueprint reveal.

## Trigger
User prompt **"VisionAir Transformation Synthesis Upgrade Pass"** on 2026-04-21, scoped to `app/session/flow/transformation.tsx` and (where needed) `formatTransformation` in `app/session/page.tsx`. The pass forbade LLM/API integration, UI restructuring, and modification of reflection logic, blueprint rendering, doctrine, or other flow screens.

## State Observed (pre-execution)
- `app/session/flow/transformation.tsx`: live "Your transformation promise" card just template-concatenated raw input — `You help someone move from ${beforeValue} toward ${afterValue}.` — echoing the user's words verbatim.
- `app/session/page.tsx`: `formatTransformation(before, after)` produced `This system helps someone move from ${before.trim()} toward ${after.trim()}.` — same raw echo, fed into `BlueprintData.transformation` and rendered in the Blueprint reveal screen.
- Both surfaces violated the Structural Constraint Layer: emotional phrases ("lost", "worthless", "seen", "valued") would round-trip into the artifact unchanged.
- No translation table existed in the transformation file. The reflection translator was scoped to `reflection.tsx` and not exported.

## Action Taken
Two files modified — both within the user-defined scope.

### `app/session/flow/transformation.tsx` (rewritten)
- Added two regex translation tables tuned for the transformation surface:
  - `beforeTranslations` (24 entries): maps problem-state phrasing into structural state descriptions. Examples:
    - `lost` → "operates without a defined direction"
    - `worthless` → "operates with no recognized capability"
    - `overwhelmed` → "carries more input than current structure can absorb"
    - `safe space` → "lacks a structured environment to surface signal without performance pressure"
    - `finding (my/their) worth` → "has not yet separated capability from identity in a recognizable way"
    - `becoming (myself/themself)` → "is in an identity-shaping phase without a stable functional anchor yet"
  - `afterTranslations` (23 entries): maps resolved-state phrasing into structural outcome descriptions. Examples:
    - `clear`/`clarity` → "has named, usable structure for the current situation"
    - `confident`/`confidence` → "has self-trust grounded in observable capability"
    - `seen` → "has had real signal accurately reflected back, which becomes ground for action"
    - `aligned`/`alignment` → "has matched capability to direction in a way that supports action"
    - `know what` → "has a usable decision map for next moves"
- Added `dedupe()`, `translateState()`, and exported `structuralizeBefore()` / `structuralizeAfter()` functions.
- Each structuralizer:
  1. Trims and short-circuits to a 3-bullet fallback for empty input.
  2. Runs the appropriate translation table and dedupes matches.
  3. Returns up to 3 bullets prefixed with `"The current state ..."` (before) or `"The new state ..."` (after).
  4. If no matches found on non-empty input, returns a 3-bullet generic structural fallback (still no echo, still functional).
- Replaced the synthesis card's `<p>` echo with a 2-column structured Before/After bullet grid (inside the same outer `mt-6 rounded-2xl` container — the card position, padding, and screen layout are unchanged).
- Added `showBullets` flag: true when either side has text, false when both empty. Empty-empty case keeps a soft placeholder; once typing begins, structured bullets appear with fallbacks for whichever side is still empty.
- Outer page layout, ScreenShell, ScreenIntro, textareas, and Back/Continue buttons are unchanged.
- `canContinue` enable logic unchanged.

### `app/session/page.tsx` (minimal edit)
- Updated the `Transformation` import to also pull `structuralizeBefore` and `structuralizeAfter` as named imports.
- Rewrote `formatTransformation(before, after)` to use the structuralizers. It now returns a single coherent string (`Before — <2 bullets joined>  After — <2 bullets joined>`) so the existing Blueprint `SectionCard` renders the structurally translated promise without any change to `blueprint.tsx`.
- Empty-empty case still returns `''` so the SectionCard displays its existing "Still taking shape." placeholder.
- No other code in `page.tsx` was touched (formatters, step machine, render switch, state types, blueprint data assembly all unchanged).

### Out-of-scope explicitly preserved
- `reflection.tsx`: untouched
- `blueprint.tsx`: untouched
- `formatProblemSpace`, `formatOpportunityForm`, `formatCapability` in `page.tsx`: untouched (they belong to other application surfaces, not yet upgraded)
- All other flow screens: untouched
- Doctrine, growth map, contracts, reports system: untouched
- `console.log("SYNTHESIS RUNNING", …)` from the verification pass remains in `reflection.tsx` only

### Translation table reuse decision
The translator data structurally mirrors what reflection.tsx uses but the bullet templates and many entries are surface-specific (problem-state vs resolved-state). I did **not** extract a shared module; the user's scope explicitly limited modification to two files, and creating a new `lib/synthesis.ts` (or similar) would introduce an unauthorized folder. The duplication is recognized and called out as an open follow-up in this report's Next Move.

## Result
- Live transformation card now shows a 2-column structured Before/After view with translated bullets, replacing the raw echo
- Blueprint reveal now contains a structurally translated transformation promise instead of `"This system helps someone move from <raw input> toward <raw input>"`
- `structuralizeBefore` and `structuralizeAfter` are available as named exports from `app/session/flow/transformation.tsx` for any future surface that needs the same translation
- Structural Constraint Layer is now active on two of the seven application points (reflection, transformation)

## Validation

### Strong input (structured)
> Before: *"they feel lost and overwhelmed and don't know what they're good at"*
> After: *"they have clarity, structure, and know what to do next"*

`beforeTranslations` matches:
- `lost` → "operates without a defined direction"
- `overwhelmed` → "carries more input than current structure can absorb"
- `don't know what` → "lacks a defined map of next-step decisions"

`afterTranslations` matches:
- `clarity` → "has named, usable structure for the current situation"
- `structure` → "operates inside a defined structure"
- `know what` → "has a usable decision map for next moves"

**Live card output:**

Before:
- The current state operates without a defined direction.
- The current state carries more input than current structure can absorb.
- The current state lacks a defined map of next-step decisions.

After:
- The new state has named, usable structure for the current situation.
- The new state operates inside a defined structure.
- The new state has a usable decision map for next moves.

**Blueprint card output (via formatTransformation):**
> *Before — The current state operates without a defined direction. The current state carries more input than current structure can absorb. After — The new state has named, usable structure for the current situation. The new state operates inside a defined structure.*

No echo. No regression — the original raw phrasing is fully replaced with structural translations.

### Emotional input (second user)
> Before: *"I feel lost and worthless. Everything feels confusing."*
> After: *"I want to feel seen, valued, and confident."*

Translations:
- Before: `lost` → "operates without a defined direction"; `worthless` → "operates with no recognized capability"
- After: `seen` → "has had real signal accurately reflected back, which becomes ground for action"; `confident` → "has self-trust grounded in observable capability"

(Note: "feels confusing" doesn't match the `\bconfused\b` pattern — gerund form "confusing" is intentionally not matched. "valued" is also unmatched. Both are honest gaps in the translation table, callable as additions in a future pass.)

**Output:**

Before:
- The current state operates without a defined direction.
- The current state operates with no recognized capability.

After:
- The new state has had real signal accurately reflected back, which becomes ground for action.
- The new state has self-trust grounded in observable capability.

Emotional words "lost", "worthless", "seen", "confident" are converted to functional structural meaning. No raw phrasing carried through. Identity-language ("worthless") is explicitly re-framed as a capability-recognition gap, not a self-worth claim.

### Weak/minimal input
> Before: *"they're stuck"*
> After: *"they're free"*

- `stuck` → "is blocked by a missing next step rather than a missing ability"
- `free` → "operates without the prior structural blocker"

**Output:**

Before:
- The current state is blocked by a missing next step rather than a missing ability.

After:
- The new state operates without the prior structural blocker.

Even one-word emotional input gets a structural translation, not an echo.

### Empty/unmatched input (fallback)
> Before: *"hmm idk"*
> After: *"better i guess"*

No regex matches in either table → fallback bullets fire on both sides:

Before:
- The current state lacks a clearly named structural shape someone could act from.
- There is signal that the situation is unresolved, but it has not yet been separated into a specific functional gap.
- The starting condition is described in personal or experiential language rather than operational terms.

After:
- The new state introduces a defined structural shift, with the situation moving from unresolved to organized.
- Capability becomes nameable and usable in operation, not just recognized internally.
- There is a visible next move, replacing direction-of-search with a usable decision.

Three structured bullets per side. The user's vague phrases are not echoed. The output describes the *shape* of a transformation rather than fabricating specifics.

All non-empty input classes produce structured Before/After output; the format is consistent.

## Readiness / Next Move
**Readiness**: Two of seven Structural Constraint Layer application points are now active at runtime (reflection in v1.0.5/v1.0.6, transformation in v1.0.7). Both surfaces share the same compositional discipline: detect translatable phrasing → translate; otherwise produce structural fallback bullets; never echo raw input.

**Highest-leverage next move**: **Extract the synthesis helpers into a shared module** so the next four surfaces (problem-space, ideal-user, opportunity-form, blueprint section composition) can compose without further duplication. The reflection translator and the transformation translators have meaningfully different vocabularies, but the *machinery* (regex tables, dedupe, slice-and-prefix, fallback fan-out) is now identical across files. One small file (e.g., `app/session/flow/_synthesis.ts` or, if the user authorizes, a `lib/synthesis.ts`) would let v1.0.8 onward stay clean. This was deferred from v1.0.5; reasserting now after a second concrete duplication.

**Alternative next move**: **Continue surface-by-surface upgrade** without extraction — apply the same pattern to `ideal-user.tsx` next (similar to transformation in shape: textareas + live preview). Slightly faster per pass, but doubles the duplication debt.

**Live reality check** is also still outstanding — both reflection (v1.0.5/v1.0.6) and now transformation render structurally on the live ngrok tunnel and have not been observed end-to-end on a phone.
