# Fallback Structuralization Upgrade

## Report Version
v1.0.6

## Purpose
Close the silent-fallback gap in the reflection synthesis engine. Before this pass, an input with no theme matches and no emotional translations would fall through to the theme-led branch's `else` defaults — producing four bullets that were structured but identical for every weak input, regardless of what the user actually wrote. This pass replaces that silent fallback with an active structural read of the input shape itself, so even ambiguous, aspirational, identity-language, or fragmentary inputs receive interpretive (not generic) output.

## Trigger
User prompt **"Run a fallback structuralization upgrade pass"** on 2026-04-21, with explicit instructions to add fallback behavior that interprets weak input structurally without changing existing logic.

## State Observed (pre-execution)
`app/session/flow/reflection.tsx` already contained the v1.0.5 synthesis engine:
- emotional-dominant branch (when translations exist)
- theme-led branch (when themes exist)
- inline `else` defaults inside each theme-led bullet's ternary

When `themes.length === 0 && translations.length === 0`, the engine entered the theme-led branch and every ternary fell to its default, producing the same four generic bullets for every weak input — effectively a silent fallback. No structural read of the input was happening.

Examples that previously hit this silent fallback:
- `"I just want a meaningful life"` — no theme keywords, no emotional translations
- `"Hi"` — too short
- `"asdfjkl"` — gibberish
- `"I'm just trying to find my way"` — aspirational identity-language with no theme keywords (note: `"figured out"` regex misses `"trying to find"`)

## Action Taken
Modified only `app/session/flow/reflection.tsx`. Two non-overlapping edits:

**Edit 1**: Inserted a new helper module above `synthesizeReflection`:
- `WeakSignal` type with six structural shapes: `aspirational`, `questioning`, `self-defining`, `identity-domain`, `short`, `gibberish`
- `detectWeakSignals(text)` — regex-based detection across the six shapes
- `fallbackBullets(text)` — composes four bullets based on detected weak signals, with a dedicated path for gibberish (no readable signal at all)

**Edit 2**: Inserted a new branch inside `synthesizeReflection` between theme/translation detection and the emotional-dominant check:

```ts
if (themes.length === 0 && translations.length === 0) {
  return fallbackBullets(text)
}
```

No existing code was deleted. No existing branch was modified. The inline ternary defaults in the theme-led branch are now technically unreachable but were left in place per "Keep all existing logic intact." The `console.log("SYNTHESIS RUNNING", seedInput)` from the verification pass remains.

### How the fallback reads weak input

| Detected signal | Trigger pattern (illustrative) | Structural read |
|---|---|---|
| `aspirational` | `i want`, `i need`, `i'm trying`, `looking for`, `should be`, `wish` | "sits in the aspirational layer — pointing at something wanted but not yet describing what it is or how it would work" |
| `questioning` | trailing `?`, `how do`, `why am`, `what should` | "structured as a question rather than a claim — direction-of-search but no stable signal yet" |
| `self-defining` | `i am`, `i'm a`, `i'm just`, `myself`, `who i am` | "identity-language about who you are rather than functional-language about what you reliably do for someone else" |
| `identity-domain` | `life`, `purpose`, `meaning`, `calling`, `dream`, `soul`, `journey` | "sits in the personal-meaning layer — true, but not yet on the layer that converts to capability/user/buildable form" |
| `short` | text length < 30 | "fragment of signal but not enough surface to extract a pattern from" |
| `gibberish` | length > 5, vowel-ratio < 0.15, no whitespace | "no readable signal — input has not crossed into language the system can structure" |

Bullet 4 in every non-gibberish path is forward-looking and prescriptive (e.g., "name one specific person you have helped, and one specific thing that became easier for them"). Bullet 3 in every non-gibberish path re-frames the situation as a structural state, not a personal deficit. Gibberish gets its own dedicated four-bullet path that doesn't pretend there is signal to interpret.

## Result
- New helper functions: `detectWeakSignals`, `fallbackBullets`, type `WeakSignal`
- New branch in `synthesizeReflection` catches the empty-themes + empty-translations case before any other branch
- All previously-working inputs continue to flow through their original branch (theme-led or emotional-dominant)
- The Structural Constraint Layer's "do not echo raw emotional or identity phrasing" rule now holds across all five categories of input (capability-rich, emotional-dominant, aspirational, identity-language, fragment) plus the gibberish edge case

### Weak input A — aspirational + identity-domain + short
> *"I just want a meaningful life"* (29 chars)

- `translations = []` (no emotional-translation keywords match)
- `themes = []` (no theme keywords match)
- Fallback fires
- `detectWeakSignals` → `['aspirational', 'identity-domain', 'short']`
- Output:
  1. *What you shared sits in the aspirational layer — pointing at something wanted but not yet describing what it actually is or how it would work.*
  2. *The functional gap is between identity and operation: it is clearer what kind of person you are or want to be than what you would reliably do for which specific person.*
  3. *This is a normal early-stage state, not a deficit — the input is in a layer that needs structural separation, not more reflection.*
  4. *What matters now is naming one specific person you have helped or could help, and one specific thing that became easier for them — that gives the system a concrete signal to structure from.*

Four structured bullets. The phrase "meaningful life" is converted into a structural observation about layers (identity vs operation). No raw input is echoed. The forward-looking bullet is concrete and actionable.

### Weak input B — gibberish
> *"asdfjkl"*

- `translations = []`, `themes = []` → fallback
- `detectWeakSignals` → `['short', 'gibberish']`
- gibberish path returns its dedicated four bullets:
  1. *There is no readable signal in what you shared yet — the input has not crossed into language the system can structure.*
  2. *That is itself a structural observation: the first move is to put the situation into recognizable words rather than to refine what is already there.*
  3. *The capability question is downstream of having something nameable to work with.*
  4. *What matters now is producing one short, plain sentence about what is actually going on, then re-running the reflection from that.*

The system honestly names "no readable signal" rather than fabricating one, while still producing four structured, forward-looking bullets.

### Weak input C — fragment
> *"Hi"*

- `translations = []`, `themes = []` → fallback
- `detectWeakSignals` → `['short']` (gibberish requires length > 5)
- Output:
  1. *What you shared is short enough that there is a fragment of signal but not enough surface to extract a pattern from.*
  2. *The functional gap is that the input has not yet been named in terms of what someone else would receive or experience as a result.*
  3. *This is a normal early-stage state, not a deficit — the input is in a layer that needs structural separation, not more reflection.*
  4. *What matters now is going one layer deeper — write a few more sentences about a real situation where this showed up, so there is surface to structure from.*

Different from inputs A and B in content (because input shape is different) but identical in **format** (4 structured bullets, forward-looking close, no echo).

### Format consistency across all branches

| Input type | Branch | Bullets | Echoes raw input? | Forward-looking close? |
|---|---|---|---|---|
| Strong (themes ≥ 1) | theme-led | 4 | No | Yes |
| Emotional-dominant (translations ≥ themes) | emotional-dominant | 4 | No | Yes |
| Aspirational/identity (no themes, no translations) | fallback | 4 | No | Yes |
| Gibberish | fallback (gibberish path) | 4 | No | Yes |

The Structural Constraint Layer's Normalization Rule ("system should not mirror the style of the input — should extract the function") now holds across every input class.
