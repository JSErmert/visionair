# VisionAir v3 — Design Starting Point (DRAFT for operator review)

Status: **draft, 2026-06-09.** v2 is live (single-owner Build Mode). v3 = the
more powerful, multi-user evolution. This frames the work and recommends the first
slice; the operator confirms/redirects before implementation.

## Two pillars of v3

**Pillar A — Multi-tenant signup (infrastructure).** Turn the single-owner gate
into real per-user accounts so each visitor keeps their own library. This is what
stops other users' builds from "disappearing," and it is the thing that makes
external-user validation (the ExoGenius criterion) *possible* in the first place.
The schema is already designed for it: every row carries `ownerId` (hardcoded to 1
today).

**Pillar B — Persona delineation (the keystone UX).** The first question
identifies the user (technical level + target runtime), which forks both the
interview depth and the output artifact shape: developer → Claude Code pack ·
business → claude.ai Project corpus · non-technical → conversational setup. This is
the organizing axis the rest of the 18-item backlog hangs off of
(`visionair_vnext_idea_backlog`).

## Recommended first slice: Pillar A (multi-tenant signup)

Rationale: it is foundational (everything multi-user depends on it), it directly
answers the operator's "so it doesn't just disappear" concern, and it converts the
ExoGenius gate from "blocked" to "satisfiable" (real users, real libraries).

### Design sketch (to refine with operator)
1. **Accounts.** Add a `users` table (or rename/extend `owners`): `id`, `email`,
   `password_hash` (reuse the existing scrypt `salt:hash` from `auth.ts`),
   `created_at`. Keep it minimal — email + password, no third-party provider for v1.
2. **Signup + login.** `/build/signup` + the existing `/build/login`, both posting
   to an auth route that issues the same HMAC session cookie, now carrying `userId`
   instead of the implicit owner.
3. **Scope everything to the session user.** Replace `OWNER_ID = 1` with the
   `userId` decoded from the session in `server-auth.ts`; `sessions`/`versions`
   queries filter by that `userId`. The build-save path saves under the logged-in
   user.
4. **Anonymous stays first-class.** No regression to v2's open model: anyone can
   still generate + download a pack without an account; signup only unlocks a
   persistent library. (v2's optional-login model generalizes cleanly.)
5. **Migration.** The operator's existing rows (ownerId = 1) map to the operator's
   new user account, so the current library survives the cutover.

### Open decisions for the operator
- Auth method: email + password (simplest) vs magic-link vs an OAuth provider?
- Email verification required, or defer (friction vs spam)?
- Do we want this before or after Pillar B? (Recommend Pillar A first.)
- ExoGenius gate: the operator has a revised spec — does the v3 gate criterion get
  rewired to read real per-user completed sessions as the pass-signal?

## Sequencing note
Pillar A then Pillar B. The 18 backlog items (`visionair_vnext_idea_backlog`) are
mostly UX/experience layers that sit *on top of* the persona axis (Pillar B), which
in turn assumes accounts (Pillar A). So: accounts → persona fork → the experience
layers.
