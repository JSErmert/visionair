## Critical Architectural Insight

The sequence was intentionally reordered based on the v1.0.13 ultrareview triage. The decisive finding:

> **The blueprint artifact contract currently flattens structured synthesizer output via `.join(' ')` at `app/session/page.tsx:547,550,557`, which destroys the structure at the final output layer.**
>
> The same synthesizer output renders as `<ul><li>` bullets on the transformation edit screen (`transformation.tsx:177-204`) but as a single `<p>` paragraph on the blueprint (`blueprint.tsx:26-43`). The render asymmetry is the source-of-truth bug — not any individual synthesizer.

Therefore:

- **New synthesis surfaces MUST NOT be added until the artifact contract is corrected**
- **The blueprint must become the true structured output surface before additional synthesis is layered on top**
- **Landing `synthesizeIdealUser` on the current contract would bake a fourth `.join(' ')` into the data-flow path the review flags as most expensive to undo**

---

## Explicit Rule Going Forward

```text
Do not introduce new synthesis logic into a broken data contract.
Fix the data contract first, then extend synthesis.
```

Applied:
- Before any new `synthesize*` function lands, verify that `BlueprintData` types its output as `string[]` and that `SectionCard` renders `string[]` as bullets
- If a future pass is tempted to add a fifth synthesizer before v1.0.14 is done, it must stop and complete v1.0.14 first
- If a future pass is tempted to re-flatten bullets to a paragraph for stylistic reasons, it must update this document and the governing `REVIEW_FRAMING.md` before doing so

No bucket-3 ("safe to defer past v1.1.0") items exist — all seven review findings affect artifact integrity or architectural cost.
