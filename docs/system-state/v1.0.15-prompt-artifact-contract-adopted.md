## New Architectural Insight (v1.0.15)

The system previously had no formal gate between decision and execution. The Highest-Leverage Move Contract identifies the move; historically the same pass that identified it also executed it, with no sealed, copyable, reviewable intermediate artifact. That coupling made three failure modes possible:

1. **Interpretation drift** — the executor (even if it is the same agent) may interpret the move slightly differently from the decision
2. **Session-boundary amnesia** — if the session ends between decision and execution, the move must be re-derived from reports or memory
3. **Validation fabrication** — reports could be pre-written with aspirational validation, violating the Report Truth Rule

The Prompt Artifact Contract closes all three by introducing a Prompt Generation Layer with:
- a sealed, copyable artifact between decision and execution
- a mandatory human gate before code changes
- a Re-Entry Validation Rule that forces post-execution validation before any report is written

## Explicit Rules Going Forward

```text
1. Do not introduce new synthesis logic into a broken data contract.
   Fix the data contract first, then extend synthesis.

2. When asked to "Create sealed execution artifact for vX.Y.Z" or
   "Enter prompt-generation mode for vX.Y.Z," output exactly one
   fenced markdown artifact per docs/prompt-artifact-contract.md.
   Do not execute, do not modify code, do not write reports.

3. After execution of any sealed artifact, apply the Re-Entry
   Validation Rule before writing the corresponding report.

4. No validation claim in any report may be pre-written. Reports
   are written after execution with actually-observed validation.
```

## Fencing-Rule Interaction (resolved)

Memory rule: *"every assistant text reply in VisionAir is wrapped in a single 4-backtick `md` fence"*.
Prompt Artifact Contract rule: *"Output MUST be exactly one fenced markdown artifact. No text, explanation, or commentary may appear before the artifact."*

**Resolution:** Both rules compose with no conflict. The outer 4-backtick `md` wrapper is the standing VisionAir chat-reply shape. When in prompt-generation mode, the wrapped content is a single 3-backtick sealed artifact — nothing before it, nothing after it — preserving the "one fenced artifact" requirement at the content level.

Outside prompt-generation mode (reports, triage, execution summaries), the existing composition of commentary + fenced report / artifact per the Report Contract continues.
