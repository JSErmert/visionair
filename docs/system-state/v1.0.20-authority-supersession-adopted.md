### §3 — Rationale (with preserved-vs-rejected acknowledgment)

Governance contracts must be installed before further execution passes to prevent repeated silent governance drift. The v1.0.18 memo-pass → re-seal cycle demonstrated empirically that contract-grade quality requires pre-execution review; that pattern is being formalized in v1.0.19. The v1.0.19 memo-pass in turn exposed that the system had no formal mechanism for superseding prior authoritative decisions; that gap is being closed in this pass, v1.0.20.

**The ultrareview-derived bucket-2 ordering (bug_011 → bug_014 → bug_006 → bug_005) is preserved and deferred by two slots, NOT rejected.** The review's substantive prioritization of user-trust fixes before v1.1.0 user testing remains correct and intact. Only the version numbering shifts forward by two. The sequence of fixes, the fixes themselves, the priority ordering, and the v1.1.0 milestone gate are unchanged.

What was considered and consciously chosen in this supersession:
- Considered: executing v1.0.19 directly as bug_011 per v1.0.15, and deferring the governance contracts.
- Rejected: the informal memo-pass pattern has already saved the system from at least one would-have-been-regression (v1.0.18 Edit #1, M1 classification). Further code execution without formal pre-review is a governance risk that compounds with each new sealed artifact. Installing the governance layer now prevents that compounding.
- Preserved: the entire ultrareview-derived bucket-2 sequence and v1.1.0 gate.
