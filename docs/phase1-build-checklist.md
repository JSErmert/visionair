# VisionAir Phase 1 Build Checklist  
  
## Purpose  
This is the compact execution companion to the full **VisionAir Phase 1 Sacred Experience Build Spec**.  
  
Use this document during active development to keep Phase 1:  
- faithful  
- focused  
- non-drifting  
- buildable  
  
This is the fast-operating version.  
  
---  
  
## Phase 1 mission  
Build one sacred experience that helps a capable but unclear nontechnical person move from:  
  
**“I know there’s something here, but I can’t structure it.”**  
  
to:  
  
**“I can clearly see what I have, who it helps, what it should become, and what my first real move is.”**  
  
---  
  
## First user  
### Build for:  
**Capable but unclear nontechnical builder**  
  
### They are:  
- skilled or insightful  
- meaningful but unstructured  
- blocked by lack of clarity / direction / trusted progression  
- trying to turn something real inside them into something real outside them  
  
### Do not dilute this user.  
Do not optimize Phase 1 for:  
- everyone  
- generic founders  
- generic creators  
- broad startup audiences  
  
---  
  
## Required Phase 1 output  
### Must produce:  
**Structured Opportunity Blueprint**  
  
### Must include all 7 sections:  
1. Core Capability  
2. Aligned Problem Space  
3. Ideal User  
4. Transformation Promise  
5. Opportunity Form  
6. First Buildable Version  
7. Guided Path Forward  
  
### If the blueprint is missing, weak, or generic:  
Phase 1 is not done.  
  
---  
  
## Required emotional arc  
The session must move the user through:  
  
**Relief -> Recognition -> Alignment -> Belief -> Agency**  
  
### If the user only feels “inspired”:  
Phase 1 is incomplete.  
  
### If the user leaves clearer and able to move:  
Phase 1 is working.  
  
---  
  
## Must-have components  
These components are mandatory.  
  
### 1. Permission to begin  
User must feel safe to start without perfect clarity.  
  
### 2. Starting-point selection  
User must be able to begin from:  
- something they’re good at  
- a problem they care about  
- an idea  
- a direction  
- uncertainty itself  
  
### 3. Seed signal capture  
User must be able to describe what feels real in natural language.  
  
### 4. Reflection back  
VisionAir must reflect early truth signals in a way that feels accurate.  
  
### 5. Capability clarification  
System must help user see their real value pattern.  
  
### 6. Problem-space alignment  
System must help user identify a meaningful problem space.  
  
### 7. Ideal-user definition  
System must guide toward one first human being this should help.  
  
### 8. Transformation definition  
System must define what changes for that user.  
  
### 9. Opportunity-form recommendation  
System must suggest the right first container.  
  
### 10. First-buildable-version grounding  
System must help define version one and prevent overbuilding.  
  
### 11. Blueprint reveal  
System must generate a structured artifact.  
  
### 12. Guided next steps  
System must leave user with immediate, near-term, and later actions.  
  
---  
  
## Screen build order  
Build in this order only:  
  
1. Welcome / Permission  
2. Starting Point Selection  
3. Seed Prompt  
4. Reflection Back  
5. Capability Clarification  
6. Emerging Capability Pattern  
7. Problem Space Discovery  
8. Ideal User Builder  
9. Transformation Promise  
10. Opportunity Form  
11. First Buildable Version  
12. Blueprint Reveal  
13. Guided Path Forward  
14. Closing Reflection  
  
### Rule  
Do not jump ahead to later screens before early trust-building screens are strong.  
  
---  
  
## Must-pass quality conditions  
  
### Entry safety  
- user feels safe to begin  
- no shame / no pressure / no performance energy  
  
### Reflection quality  
- system reflections feel accurate  
- user feels seen, not processed  
  
### Capability clarity  
- user better understands what they are actually good at  
  
### Alignment quality  
- chosen path feels fitting, not random  
  
### Artifact trust  
- final blueprint feels believable and usable  
  
### Movement quality  
- user leaves knowing what they can do next  
  
---  
  
## Pass / fail test  
### Phase 1 passes if users can say:  
- I feel clearer  
- this fits me  
- this helped me understand what I actually have  
- I trust the output  
- I know what to do next  
  
### Phase 1 fails if users say:  
- this was interesting but vague  
- I still don’t know what I have  
- this felt generic  
- I feel inspired but not more able to move  
- the output doesn’t feel like me  
  
---  
  
## Content rules  
### Must feel:  
- calm  
- perceptive  
- grounded  
- intelligent  
- human-centered  
- structured  
- trustworthy  
  
### Must not feel:  
- hype-driven  
- generic coaching  
- startup hustle language  
- dashboard productivity software  
- robotic questionnaire  
- overpolished nonsense  
  
### Content rule  
Truth before eloquence.  
  
---  
  
## UX rules  
### Must feel:  
- spacious  
- calm  
- premium but warm  
- guided  
- emotionally safe  
  
### Must not feel:  
- like a form wizard  
- like startup software  
- like a productivity app  
- like a chat gimmick  
  
### UX rule  
Each screen should do one thing:  
- reduce pressure  
- reveal truth  
- narrow alignment  
- shape the path  
- increase trust  
- restore agency  
  
---  
  
## Synthesis rules  
### VisionAir must:  
- identify real signal  
- reflect back patterns clearly  
- preserve user truth where possible  
- reduce vagueness  
- avoid flattening the user  
- create authored-feeling structure  
  
### VisionAir must not:  
- hallucinate precision  
- overstate certainty  
- exaggerate the user  
- polish nonsense  
- output generic startup language  
  
### Synthesis rule  
The user should feel:  
> “This came from me, but I couldn’t have structured it this clearly on my own.”  
  
---  
  
## Forbidden in Phase 1  
Do **not** build these before the sacred experience is proven:  
  
### Platform sprawl  
- many personas  
- broad ecosystems  
- community  
- dashboards  
- multi-flow complexity  
  
### Startup-tool drift  
- founder productivity framing  
- launch dashboards  
- traction language  
- hustle aesthetics  
  
### Premature automation  
- advanced orchestration for show  
- complex branching too early  
- deep multi-agent logic before the core flow works  
  
### Decorative complexity  
- visual richness without function  
- symbolism that does not reduce fog  
- interactions that distract from clarity  
  
### Late-stage business tooling  
- investor tools  
- advanced business planning  
- financial systems  
- scaling modules  
  
---  
  
## MVP interpretation  
A true MVP is:  
  
> the smallest faithful version of the sacred experience that still creates real clarity, trust, and movement.  
  
### Acceptable MVP compromises  
- mocked synthesis  
- simple export  
- limited branching  
- manual support in places  
  
### Unacceptable MVP compromises  
- no reflection quality  
- no blueprint artifact  
- no real next steps  
- inspiration without movement  
  
---  
  
## Build priority stack  
### Priority 1  
Can the user feel seen clearly enough to move?  
  
### Priority 2  
Can the product turn vague internal truth into structured external form?  
  
### Priority 3  
Can the user trust the output enough to act on it?  
  
### Priority 4  
Can the session preserve coherence from start to finish?  
  
### Priority 5  
Can future layers wait until this is proven?  
  
---  
  
## Development decision filter  
Before building anything, ask:  
  
### 1. Does this strengthen the sacred experience?  
If no, do not build it yet.  
  
### 2. Does this reduce fog or increase agency?  
If no, do not build it yet.  
  
### 3. Does this preserve VisionAir’s identity?  
If no, do not build it yet.  
  
### 4. Would this belong if VisionAir were invented from scratch today?  
If no, do not build it yet.  
  
### 5. Is this depth or distraction?  
If distraction, cut it.  
  
---  
  
## Exit criteria  
Phase 1 is complete only when:  
  
- the sacred experience is real  
- users feel seen and clarified  
- the blueprint is trustworthy  
- users know what to do next  
- the experience still feels faithful to the founding doctrine  
  
### Final test  
If nothing beyond Phase 1 were ever built, would this experience already justify VisionAir’s existence?  
  
If no, keep building Phase 1.  
  
---  
  
## One-line execution compass  
**Build only what helps the first user move from fog to structured agency in a way they can trust.**
